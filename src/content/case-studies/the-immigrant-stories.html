Publishing · Selling a digital book

How we built a custom plugin so The Immigrant Stories could sell its book online without it being passed around

The Immigrant Stories wanted to sell a book on its own website and take payment by card through Stripe. Its marketer set strict conditions: each buyer gets a private link that only they can use, and the book cannot be downloaded or easily copied. No existing WordPress plugin did all of that, so we built one. After five rounds of changes it did exactly what the client asked for.

The client

Who The Immigrant Stories is

The Immigrant Stories, founded by Samuel Ukeke, is a platform built by immigrants for immigrants. It publishes real stories of people who have built new lives abroad, step-by-step immigration guides, a podcast, and practical tools such as UK visa cost and points calculators.

The team wanted to sell a book directly to its audience on its own website, rather than through a bookshop that takes a large cut and owns the customer relationship.

The brief

Sell the book, but keep it from being shared

A digital book has one big weakness: once someone has the file, they can send it to anyone. One paid copy can become a hundred free ones overnight. The marketer's conditions were designed to stop that.

Why an off-the-shelf plugin would not do

WordPress has many plugins for selling digital products, but none fitted this brief. Most simply email the buyer a file to download, which is the very thing the marketer wanted to avoid. Others lock content behind a full membership system with accounts and passwords, which adds friction for someone buying one book. Rather than force the client to accept a compromise, we built a plugin that did exactly what was asked.

What we did

Four parts, each tied to a business need

We use AI to write code faster, but the code is the easy part. The value is in turning a marketer's conditions into rules the software can enforce, and in testing with the client until it works the way they imagined. Each part below starts from one of those conditions.

Stripe payments that deliver the book by themselves

Need
Take card payments and get the book to each buyer straight away, without staff sending anything by hand.
What we built
The website listens for Stripe's "payment complete" message. Before acting on it, the plugin checks a secret signature so that only genuine messages from Stripe are accepted and nobody can fake a purchase. It then creates the buyer's private link and emails it to the address they used at checkout, with plain instructions on how the link works.
Result
Sales are delivered in moments, day or night, with no manual work. Fake purchase requests are rejected.

A private link that only works for the person who paid

Need
Stop a link being forwarded to friends or shared in group chats.
What we built
Each link carries a long random code that cannot be guessed. The first time the buyer opens it, the link locks itself to that browser. The client chose to allow two devices, so a buyer can read on both laptop and phone. A third device, such as a friend's phone, sees an "already claimed" message instead of the book. Links can also expire after a set number of days and carry a generous limit on how many times they can be opened.
Result
One payment gives one reader access. Sharing the link no longer gives the book away, and buyers do not have to create an account or remember a password.

A reader that keeps the book on the website

Need
Let buyers read comfortably while making it impractical to download, save or copy the book.
What we built
The book opens in a reader on a private page of the website and is shown one page at a time, drawn as an image rather than as text that can be selected and copied. There is no download button. Right-click and the save, print and view-source keyboard shortcuts are switched off on the page. The real location of the book file is never shown in the browser: each time the reader loads, the website issues a permission that expires after two minutes, so a copied address stops working almost at once. The reader also shows the buyer when their link expires and how many views they have left.
Result
Buyers get a simple reading experience, and the book stays where the client can control it. No website can stop someone photographing a screen with a second phone. The aim was to make saving and sharing the book impractical, and the client signed this off.

A dashboard to see every buyer and help them

Need
Know how many people have bought the book, whether they have opened it, and sort out problems quickly.
What we built
A page in the WordPress admin listing every buyer: their email, when they bought, how many devices they have used, how many times they have opened the book, when their link expires, and its status (active, expired, view limit reached or devices full). Each buyer has one-click actions: give more days, add more views, reset their devices when they get a new phone, or cancel the link, for example after a refund. The same page holds the settings: how long links last, how many views and how many devices each link allows.
Result
The team can see sales and reading activity at a glance, and fix any buyer's problem in seconds without calling a developer.

Getting it right

Five rounds to get the balance right

A plugin like this has to balance two things that pull against each other: strict protection for the client, and an easy experience for honest buyers. Too loose, and the book gets shared. Too strict, and paying readers get locked out and ask for refunds. We worked through five versions with the client. Along the way we:

  • allowed two devices per link, so buyers can move between laptop and phone;
  • raised the view limit so that normal reading never hits it, and fixed early links that had been set too low;
  • removed an occasional failure where the book would not load on the first try, by making each page's permission self-checking instead of waiting on the database;
  • added the dashboard tools to extend, reset or cancel any buyer's link in one click.

Version five was the one the client wanted.
